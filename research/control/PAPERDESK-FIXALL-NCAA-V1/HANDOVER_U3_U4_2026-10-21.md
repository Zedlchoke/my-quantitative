#### State machine laws

* Slots = config order (`model_id` first, then `fallback_models`),
  strongest-first. The producer never re-orders; each provider request
  names exactly ONE model (OpenRouter never receives a fallback array).
* Per-slot persisted state in `ai_review/cascade_state.json`
  (sandbox plane aware): `{state: UP|COOLDOWN|HALF_OPEN,
  cooldown_until_utc, cooldown_reason, consecutive_failures,
  last_cooldown_min, config_broken, soft_fails_utc[]}`.
* A pass requests the FIRST available slot: `config_broken` and
  `COOLDOWN` slots are skipped; `HALF_OPEN`'s request is the trial.
  Within one candidate, garbage-fallen slots are never re-dialed
  (per-candidate skip set).

#### Trigger table (typed seam: `ProviderHTTPError` carries `.status`
and parsed `Retry-After`; `urllib.error.HTTPError.code` is also
classified where reachable; everything below HTTP = TRANSIENT)

| Trigger | Effect |
|---|---|
| 429 | slot COOLDOWN `max(Retry-After, 15 min)`; fall to next slot for the candidate |
| 402 | ALL paid slots (id NOT ending `:free`) COOLDOWN indefinite (until a successful balance check) + `AI_LOW_BALANCE` event; free slots keep producing |
| 5xx / timeout | fall; slot COOLDOWN 10 min, doubling per consecutive failure, capped 4 h |
| garbage output | retry the SAME model ONCE with the JSON-law suffix appended to the user payload; still bad -> fall for the candidate + soft fail; 3 soft fails in 1 h -> COOLDOWN 30 min |
| 400 / 404 | slot CONFIG_BROKEN (removed until config change) + `AI_CONFIG_BROKEN` event for the owner |
| 401 / 403 | `AI_KEY_ALARM` event + ALL slots COOLDOWN 30 min |
| COOLDOWN expired | HALF_OPEN: next REAL scoring attempt is the trial — success -> UP + counters reset; failure -> COOLDOWN doubled (cap 4 h) |
| success (any state) | UP, counters/soft-fails reset, `CASCADE_SLOT` event |

Every transition journals a `CASCADE_SLOT` gate event
(model, from_state, to_state, trigger) via `ai_gate_v2.gate_event`.

Other U3 laws implemented:

* Request bodies carry `"data_collection": "deny"` and
  `"require_parameters": true` (every request).
* `check_balance(endpoint, key)` — GET `https://openrouter.ai/api/v1/key`
  (derived from the chat endpoint) with Bearer; transport-injectable;
  returns USD remaining or None (unlimited/failed check never crashes
  and never revives a held slot). Runs at producer start and on 402.
  Below `low_balance_usd` -> `AI_LOW_BALANCE`; a successful check at or
  above the floor revives balance-held paid slots at producer start
  (never mid-candidate — no retry ping-pong).
* Budget clock: a producer round stops (remaining candidates stay
  pending, un-stamped) when `max_budget_seconds` elapses.
* QD2 silence law: ALL slots down -> candidates stay pending, producer
  returns, no opinion, no crash. U0 citation filter and parse_v2 laws
  untouched and still battery-covered.
