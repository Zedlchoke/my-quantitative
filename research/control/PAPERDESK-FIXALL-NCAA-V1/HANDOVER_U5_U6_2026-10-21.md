### 1. Scoreboard by the MATCH's kickoff date (+ today's when different)

`collect_evidence(..., kickoff_utc=None, team_ids=None)` — both params
OPTIONAL, so the existing call sites (`ai_producer.py`, `execute.py
ai-evidence`) keep working byte-identically until wired.

- kickoff date board fetched via
  `https://site.api.espn.com/apis/site/v2/sports/{path}/scoreboard?dates={YYYYMMDD}`
  (dates param derived from `kickoff_utc`; unparsable kickoff → today only,
  noted honestly, never guessed);
- today's board added WHEN the two dates differ — a T-6h10m decision for
  TOMORROW's match now has a real status source;
- every board fetch is journaled in `queries` (`dates=` in the line); when the
  event is on the board → one source
  `{url: "...scoreboard?dates={day}#event={match_id}", excerpt: status
  type.detail, kind: "scoreboard_status"}`; when NOT → journaled in
  `scoreboard_notes` as absent/ERROR with ZERO sources — never invented.

### 2. Roster-name news filter (first+last passes without the team name)

- Rosters: `https://site.web.api.espn.com/apis/site/v2/sports/{path}/teams/{team_id}/roster`
  (team ids via the new `team_ids` param: `{"home": id, "away": id}` or a
  2-sequence; absent ids simply skip this layer);
- module-level cache `_ROSTER_CACHE` keyed `(league, team_id, YYYYMMDD)` —
  AT MOST ONE fetch per team per day (errors cached too; battery-tested);
- news filter now passes on `team-name hit OR first+last roster name hit`
  (single-word names never match — no false positives);
- battery: the star-player injury headline "Jalen Williams (knee) listed out"

### 3. Per-team injuries source — EXACT ENDPOINT USED

```
https://sports.core.api.espn.com/v2/sports/{sport}/leagues/{league_slug}/teams/{team_id}/injuries
```

Keyless JSON (no API key, public GET). `sport`/`league_slug` derived from the
existing `SPORT_PATH` two-part paths (`basketball/nba` →
`sports/basketball/leagues/nba`). Chosen over the site news variant because it
returns the injury items directly for one team.

- each readable injury item → one source
  `{url: <endpoint>, fetched_at_utc, excerpt: "Name — Status — Detail",
  published_utc: item.lastUpdate, kind: "injuries"}`; pure-`$ref` items
  without readable text are skipped, never invented;
- 404 / any error → journaled in `queries` (ERROR, 0 sources) +
  `injuries_errors` — honest zero-source, per the law;
- `SOCCER`/`WSL` have a one-part `SPORT_PATH` (no league slug): NO URL is
  invented; journaled in `injuries_notes` with zero sources. Wiring a soccer
  slug (e.g. `eng.1`) later is a `SPORT_PATH` value change only.

## U6 — CLV MEASUREMENT PLANE (`research/papertrade_exec/clv_plane.py`, NEW)

MEASURE ONLY: writes sidecar JSON + reports. No ledger writes, no gate reads
beyond the rows passed in, no decisions.

### Exact integrator signature (one-page usage note)

```python
from research.papertrade_exec import clv_plane

summary = clv_plane.record_closing_quotes(
    *, ledger_rows,        # the ledger JSONL rows (list of dicts) as of now
    data_root,             # Path — same data root as the runner
    sandbox,               # bool, EXPLICIT: False -> <data_root>/ops/clv/
                           #            True  -> <data_root>/sandbox/ops/clv/
    odds_fetch,            # callable(sport_key, match_ids) -> payload
    pm_fetch,              # callable(home, away) -> {leg: price} | None
    now_utc,               # tz-aware datetime (naive treated as UTC)
    sport_keys=None)       # optional {"LEAGUE": "sport_key"} override;
                           # defaults to execute.DEFAULT_SPORT_KEYS
```

- call it ONCE per ops tick near kickoff; it is STATELESS and makes exactly
  ONE `odds_fetch` call per league (all of the day's match_ids in one call —
  quota-friendly); scheduling stays with the caller;
- `odds_fetch` payload: either `{"<match_id>": {"HOME": 1.9, ...}}` (already
  normalized by a wrapper) or a raw The-Odds-API-style event list (parsed
  here with strict pinnacle-h2h preference and home/away full-name matching;
  unmapped → `NO_RUN_PINNACLE`, never a stand-in book);
- ANY `odds_fetch` exception (incl. `quota_guard.ProviderQuotaSkip`) →
  `pin_status="NO_RUN_PINNACLE"`, `why_pin="quota skip: …"` — recorded, never
  invented, never retried inside;
- `pm_fetch(home, away)` → `{"HOME": 0.53, "AWAY": 0.49}` (probabilities
  0..1) or `None`/`{}` → `pm_status="NO_RUN_PM"` with reason;
- ONE record per match per day: `clv_{league}_{match_id}_{YYYYMMDD}.json`,
  same-day re-call overwrites (keyed by `sampled_at_utc` inside);
- for EVERY match with a FORECAST row (placed or not): no-vig pin close
  `p = (1/odds)/Σ(1/odds)` + the raw decimals, PM close, plus — when the row
  exists — `entry` (chosen_leg/entry_decimal from the BET_PAPER DECISION) and
  `forecast_quote` (latest MARKET_QUOTE) for the drift measurement;
- report: `clv_plane.clv_report(sidecar_dir)` → per league:
  `clv_pin = entry/close − 1`, `clv_pm = entry·pm_price − 1` (pm decimal
  close = 1/price — same formula once), mean/median/n; `decision_drift` =
  forecast-time quote vs pin close, mean over common legs; month buckets
  (sampled month); status census. Read-only.
